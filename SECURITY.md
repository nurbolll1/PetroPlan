# Безопасность сайта «лист.»

Сайт работает на GitHub Pages и пока полностью статический. Данные каталога и корзины хранятся в localStorage **каждого отдельного браузера**, без авторизации и облачной синхронизации. Не храните здесь пароли, ключи, документы и другую конфиденциальную информацию.

## Защита проекта GitHub

1. Включите **двухфакторную аутентификацию** на GitHub (Settings → Password and authentication).
2. В репозитории Settings → Collaborators and teams/Manage access проверьте, что запись доступна только доверенным участникам.
3. В Settings → Branches/Rulesets защитите ветку main: изменения через pull request, запрет force push и удаления ветки (некоторые правила для публичного репозитория могут зависеть от типа аккаунта).
4. Проверьте Settings → Actions → General и ограничьте права GitHub Actions до Read repository contents, если публикация не требует записи. GitHub Pages сейчас публикуется из main/(root).
5. Не добавляйте секреты в index.html, другие публичные файлы репозитория или историю коммитов.

## Защита пользователей

- Импорт JSON и CSV ограничен по размеру; JSON проверяется перед загрузкой в приложение.
- Пользовательские названия/эмодзи экранируются при отображении.
- Динамические кнопки продуктов и корзины не собирают JavaScript из пользовательского ID.
- CSV-поля, похожие на формулы, экранируются для открытия в таблицах.

## Важные ограничения

GitHub Pages — **публичный хостинг**: любой может открыть сайт и скачать HTML/JS. Защита доступа паролем с помощью одного клиентского JavaScript не обеспечит приватности. Cloudflare WAF/Access не защитит стандартный URL `*.github.io` без переноса трафика на собственный домен и корректной настройки DNS; при этом исходный URL GitHub Pages нужно закрыть/заменить, иначе его смогут открыть напрямую.

Сайт не содержит серверной базы пользователей. Изменение данных в своём браузере не меняет чужие корзины или исходный код сайта. Доступ к GitHub аккаунту, наоборот, позволяет публиковать изменения — поэтому 2FA и защита main особенно важны.

Пример AI Worker в `examples/ai-worker.js` — **не развернутый компонент**. Перед любым реальным подключением ИИ нужны авторизация или другая серверная защита от злоупотребления, лимит запросов и ограничения расходов. Один CORS не обеспечивает защиту от посторонних вызовов.
